# Ghidra / 二进制优先工作流

对于无尽核心战斗机制，`../PlantsVsZombies-decompilation` 反编译源码只能作为函数定位、结构理解和候选逻辑参考，不能作为最终权威。修改或审查 PE 的核心机制时，应优先以 PvZ 1.0.0.1051 原版二进制为准。

二进制核对优先使用 Ghidra CodeBrowser / Listing / Decompiler；但如果 Kilo 的 Ghidra MCP bridge 无法连接、无法加载工具 schema、实例项目名显示为 `unknown`，或出现类似 `Schema fetch failed: module 'socket' has no attribute 'AF_UNIX'` 的 Windows socket 兼容问题，不得因此阻塞任务。此时应直接使用 `objdump -d -Mintel`、`objdump -s` 等工具对 `PlantsVsZombies.exe` 做机器码级核对。

`objdump` 核对与 Ghidra Listing 核对同属二进制真相来源；反编译源码不能覆盖二进制结论。使用 `objdump` 替代 Ghidra 时，应在结论中明确标注 Ghidra GUI/MCP 状态，并列出关键函数地址、分支地址、常量地址或相关机器码证据。

尤其涉及以下内容时，默认需要用 Ghidra、`objdump` 或真实运行验证复核二进制行为：

- 僵尸、植物、子弹、griditem 的核心更新逻辑。
- 出怪、波次刷新、权重、随机范围、同屏限制。
- 碰撞判定、溅射、火抗、防具、门板、梯子、冰车等交互。
- 计时帧、状态倒计时、动画驱动但会影响战斗的状态。
- 常量值、比较方向、边界条件、`>` / `>=` / `<` / `<=`。
- 原版字段偏移、枚举值、状态机分支、虚函数调用。
- 任何“按反编译源码修 PE”会改变无尽测算结果的地方。

工作流：

1. 先查 `反汇编项目的错误.md`、`pe模拟器问题合集.md`、`已经修改的bug合集.md`，确认是否已有结论。
2. 如果涉及无尽核心机制，不要只看 `../PlantsVsZombies-decompilation`；应打开 Ghidra 项目或用 `objdump` 复核对应函数。Ghidra MCP 不可用时，直接改用 `objdump` 继续核对。
3. Ghidra Decompiler 只能作为理解辅助；关键结论应同时看 Listing 反汇编、常量地址、分支条件和控制流。
4. 对分支极性、浮点常量、整数常量、帧数、边界条件等敏感点，优先用 `objdump` 或 Ghidra Listing 确认机器码。
5. 如果二进制结论推翻反编译源码，应记录到 `反汇编项目的错误.md`，注明函数、地址、二进制逻辑、反编译源码错误点和 PE 影响。
6. 如果确认是 PE bug，应记录到 `pe模拟器问题合集.md`；修复后写入 `已经修改的bug合集.md`，并从 `pe模拟器问题合集.md` 移除。
7. 如果差异属于 [机制差异](机制差异.md)声明的无尽测算取舍、表现层缺失、UI/商店/小游戏等非目标范围，不要因为 Ghidra 中原版存在该系统就默认补进 PE。
